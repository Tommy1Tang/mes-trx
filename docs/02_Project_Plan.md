# 迈克生物试剂生产MES系统项目开发计划
## 1. 项目概述
### 1.1 项目目标
基于RuoYi框架开发符合GMP要求的试剂生产MES系统，实现生产全流程数字化管理，对接SAP/WMS/OA/思宇UDI等现有系统，提升生产效率，保证数据合规性。
### 1.2 总周期
6个月（24周）
### 1.3 交付物
- 完整可运行的MES系统（PC端+移动端）
- 数据库设计文档、接口文档、操作手册
- 测试报告、上线报告
- 源代码、部署文档

## 3. 模块开发顺序与依赖关系（按数据依赖逻辑调整）
```
优先级1（基础依赖，第5-6周）：
├─ 系统框架改造（新增生产模块目录、权限配置）
├─ 基础数据模块（产品、BOM、工艺路线、工作中心）
└─ 数据字典配置（生产相关枚举值）

优先级2（核心基础层，第7-10周，所有上层模块的基础）：
├─ 生产订单模块（核心主数据，所有模块的上游依赖）
└─ 物料管理模块（基础业务流程，依赖生产订单）

优先级3（计划层，第10-12周，依赖基础层数据）：
└─ 排产管理模块（依赖生产订单、物料齐套数据）

优先级4（执行层，第12-15周，依赖计划层输出）：
├─ 派工单管理模块（依赖排产结果和生产订单数据）
├─ 现场报工模块（依赖派工单数据）
└─ 订单关闭管理模块（依赖前面所有模块的生产数据）

优先级5（质量/管理层，第15-17周，依赖全量生产数据）：
├─ 电子批记录模块（依赖前面所有模块的生产数据）
└─ 异常管理模块（关联所有生产模块的异常数据）

优先级6（集成层，第17-20周，对接所有模块和第三方系统）：
├─ SAP集成
├─ WMS集成
├─ OA集成
└─ 思宇UDI系统集成
```
#### 依赖逻辑说明：
1. **基础层先开发**：生产订单是所有模块的核心主数据，物料是核心业务流程，没有这两个模块，上层所有功能都无法开发测试
2. **计划层依赖基础层**：排产需要基于生产订单和物料齐套数据才能进行
3. **执行层依赖计划层**：派工单由排产结果生成，报工基于派工单进行，订单关闭依赖生产全流程数据
4. **质量/管理层依赖执行层**：批记录需要采集全流程生产数据，异常来自各执行环节
5. **集成层最后开发**：集成需要所有业务模块功能稳定后再对接第三方系统，避免反复调整接口

### AI Coding 开发优化（基于 RuoYi Vue 前后端分离架构）
#### 开发模式调整
1. **代码生成优先**：所有模块先使用 RuoYi 代码生成器生成基础 CRUD 代码，再进行业务逻辑开发，减少重复编码工作
2. **前后端并行开发**：后端 API 定义完成后，前端可并行开发界面，通过 Mock 数据进行调试
3. **模块化并行开发**：独立模块可分配给不同 AI 代理并行开发，按照依赖顺序进行集成
4. **自动化测试同步**：业务逻辑开发完成后同步编写单元测试和接口测试，保证代码质量

#### 阶段时间优化
| 阶段 | 原时间 | 优化后时间 | 优化说明 |
|------|--------|------------|----------|
| 需求调研与设计阶段 | 第1个月（第1-4周） | 第1个月（第1-4周） | 保持不变，需求设计已完成 |
| 基础模块开发阶段 | 第2-3个月（第5-12周） | 第2个月（第5-8周） | AI 编码提速，基础模块并行开发 |
| 核心模块开发阶段 | 第4个月（第13-16周） | 第3个月（第9-12周） | 模块化并行开发，减少等待时间 |
| 系统集成阶段 | 第5个月上半月（第17-18周） | 第3.5个月（第13-14周） | 接口定义提前，集成测试并行 |
| 测试阶段 | 第5个月下半月（第19-20周） | 第4个月（第15-16周） | 自动化测试同步开发，缩短测试周期 |
| UAT阶段 | 第6个月上半月（第21-22周） | 第4.5个月（第17-18周） | 保持不变 |
| 上线阶段 | 第6个月下半月（第23-24周） | 第5个月（第19-20周） | 提前完成开发，预留更多上线优化时间 |

#### RuoYi 框架适配规则
1. 所有生产相关模块放在 `ruoyi-production` 子模块下，遵循 RuoYi 模块开发规范
2. 前端页面放在 `ruoyi-ui/src/views/production` 目录下，统一路由前缀为 `/production`
3. 权限控制遵循 RuoYi 现有权限体系，新增生产相关权限标识
4. 数据库表统一使用 `mes_` 前缀，避免与 RuoYi 系统表冲突

## 6. 上线计划
### 6.1 上线步骤
1. **灰度上线阶段（上线第1周）**：
   - 选择1-2条试点生产线，运行新系统
   - 老系统并行运行，数据双向同步
   - 实施团队7*24小时现场支持，及时处理问题
   - 每天召开上线例会，跟进问题解决进度
2. **扩大上线阶段（上线第2-3周）**：
   - 逐步扩大到所有生产线
   - 降低老系统使用频率，逐步切换到新系统
   - 优化系统性能，调整配置参数
   - 收集用户反馈，优化用户体验
3. **全量上线阶段（上线第4周）**：
   - 所有生产线完全切换到新系统
   - 关停老系统数据录入通道
   - 进行全量数据核对，确保数据一致性
   - 上线后7*24小时支持，稳定后转为正常5*8小时支持

### 6.2 风险预案
| 风险 | 发生概率 | 影响程度 | 应对措施 | 责任人 |
|------|----------|----------|----------|--------|
| 系统不稳定，出现宕机 | 中 | 高 | 部署双活集群，负载均衡，故障自动切换；准备回滚方案，随时切换到老系统；关键数据实时备份 | 架构师、运维 |
| 数据同步不一致 | 高 | 中 | 开发数据核对工具，实时监控数据一致性；发现异常立即告警，人工介入处理；每日对账，生成差异报表 | 接口开发工程师 |
| 用户操作不熟练，影响生产 | 高 | 中 | 上线前组织3次以上操作培训，制作图文操作手册和视频教程；上线期间现场手把手指导，设置热线支持；关键岗位安排专人帮扶 | 实施顾问 |
| 第三方接口不稳定 | 中 | 中 | 接口支持降级模式，离线时先缓存数据，恢复后自动同步；提供手动录入和补录功能；与第三方厂商建立紧急联系通道，问题1小时内响应 | 接口开发工程师 |
| 性能不达标，响应缓慢 | 中 | 中 | 提前做好性能压测，优化慢查询；配置缓存机制，热点数据内存缓存；必要时扩容服务器资源，采用读写分离 | DBA、架构师 |
| 数据迁移错误 | 低 | 高 | 迁移前做好全量备份；迁移后进行100%数据核对；先进行模拟迁移，验证无误后再正式迁移；出现问题立即回滚 | DBA、实施顾问 |

## 7. 项目管理规范
### 7.1 进度管理
- 每周一召开项目周会，汇报进度、问题、风险
- 每周五提交周报，同步本周进度和下周计划
- 关键里程碑节点组织阶段评审
- 延期风险提前2周预警，制定应对措施

### 7.2 质量管理
- 代码Review：所有代码必须经过架构师或资深开发Review才能合并
- Bug管理：使用Jira管理Bug，优先级明确，及时跟踪解决
- 版本管理：使用Git进行代码版本管理，遵循GitFlow工作流
- 文档管理：所有文档同步更新到项目文档库，保证最新版本

### 7.3 沟通管理
- 内部沟通：使用企业微信工作群，及时响应问题
- 客户沟通：每周至少1次客户同步会，汇报进度和问题
- 问题升级：24小时未解决的问题升级到项目经理，48小时未解决升级到更高层级
