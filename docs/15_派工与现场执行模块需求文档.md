# 派工与现场执行模块需求文档（L4+L5层）
## 1. 模块概述
负责记录现场真实执行过程，包括工序执行、报工、人工设备投入、过程跟踪和过程监控。本模块是"受控执行"的直接载体，每个执行动作都必须留痕。
派工单必须支持模板配置化，同一套派工执行能力可以按不同工序渲染不同版式和字段，并把模板版本固化到派工单实例中。

**架构层：** L4 计划订单与车间调度层（派工）+ L5 现场执行、称量与电子批记录层（执行/报工/跟踪/监控）
**涉及表：** pro_shop_floor_dispatch、pro_operation_execution、pro_production_report、pro_report_labor、pro_report_equipment、pro_operation_tracking、pro_process_monitor_session、pro_process_monitor_summary

## 3. 核心流程

### 3.1 现场执行流程
1. 执行人员接收派工任务
2. 扫码确认开工，系统校验人员/设备/物料
3. 按MBR步骤顺序执行：
   a. 确认工艺参数
   b. 扫码投料
   c. 记录执行数据
   d. 执行检验/复核
4. 扫码确认完工
5. 填报产量和工时
6. 提交报工审核
7. 审核通过后数据同步SAP

### 3.2 过程监控流程
1. 过程开始时创建监控会话
2. SCADA/ThingsBoard持续采集数据
3. MES固化关键值、摘要、告警
4. 过程结束时关闭会话
5. 摘要数据关联到EBR

### 3.3 模板派工执行流程
1. 工艺工程师维护派工单模板，配置字段、分区、明细表和打印布局。
2. 工艺工程师将模板版本绑定到指定工序或工序类型。
3. 排产下发后，系统根据工单工序匹配模板并生成派工单。
4. 系统自动带出工单、物料、配方、生产文件和前工序异常信息。
5. 车间主管确认人员、设备和执行时间后下发。
6. 执行人员按模板接收派工单、扫码开工、录入或确认字段、完工并提交报工。
7. 派工单实例、模板版本、字段值和关键操作写入审计追踪并关联EBR。

### 3.4 候选数据模型（待DBA治理评审）
- 建议新增派工单模板表，记录模板编号、模板名称、适用范围、版本、状态、启停时间和打印布局。
- 建议新增模板分区表，记录基础信息区、配方区、生产文件区、前工序异常信息区、工单需求量区等分区。
- 建议新增模板字段表，记录字段编码、字段名称、字段类型、数据来源、是否必填、显示顺序、字典编码、校验规则和打印坐标/列宽。
- 建议新增模板工序绑定表，记录模板版本与工序、工序类型、产品、物料、工作中心、订单类型的匹配关系。
- 建议新增派工单实例字段值表，记录派工单生成时的字段值和明细表数据快照。
- 上述候选模型仅作为需求口径，字段字典和DDL必须由DBA按数据模型治理规范评审后落地。

## 4. 与其他模块的关系
- L4 派工 → L5 现场执行（派工下发到执行）
- L2 MBR步骤 → L5 工序执行（按MBR步骤执行）
- L3 联锁规则 → L5 工序执行（执行时触发联锁）
- L5 报工 → L9 SAP集成（报工回传SAP）
- L5 过程监控 → L7 SCADA集成（采集数据来源）
- L5 工序执行 → L5 EBR（执行数据固化到EBR）
- L5 工序执行 → L5 称量投料（执行中的投料动作）
- L2 工艺路线/MBR → L4 派工模板（模板绑定工序和带出字段）
- L6 合规审计 → L4 派工模板（模板变更、字段录入和关键确认留痕）
