# 电子批记录模块需求文档（L5层，一期MVP重点）
## 1. 模块概述
EBR（Electronic Batch Record，电子批记录）是MBR执行快照的实际执行证据。每个工单执行时，系统根据工单/批次的MBR执行上下文生成EBR，记录每个步骤的实际执行情况，包括开始/结束时间、执行人、设备、参数实际值、检验结果、复核签名等。EBR是GMP合规的核心证据。
电子表单/DHR模板是EBR的上层平台能力，负责“表单怎么定义、怎么填报、怎么审核、怎么取数、怎么渲染、怎么归档”。EBR事实表、表单实例和DHR汇总应协同，但职责不能混淆。DHR/批记录模板只从EBR和相关业务数据中取数、组装、渲染、审核和归档，不反向驱动生产，也不能覆盖EBR原始事实。

MBR、执行快照和EBR的边界必须保持清晰：MBR镜像定义可执行模板，工单下达时生成MBR执行上下文/执行快照，EBR只记录该快照下的实际执行事实。EBR执行过程中不得实时读取PLM、BOM、工艺路线或当前MBR主镜像来改变已下达批次的执行依据；如需因ECN或异常调整，必须通过Safe Hold、上下文刷新、审批和审计追踪处理。

**架构层：** L5 现场执行、称量与电子批记录层
**涉及表：** pro_ebr_header、pro_ebr_step_record、pro_ebr_param_record、pro_batch_review、pro_line_clearance_check；电子表单/DHR候选表待DBA评审
**一期MVP：** 本模块是一期MVP的核心，必须优先实现

## 3. 核心流程

### 3.1 EBR执行流程（一期MVP核心）
1. 工单下达时基于当前有效MBR镜像生成工单/批次MBR执行上下文，并自动创建EBR头
2. EBR头必须绑定生产工单、MBR版本、执行上下文`context_id`、产品、批次号和快照哈希
3. 执行人员按执行快照中的MBR步骤顺序执行：
   a. 执行步骤操作
   b. 记录参数实际值（人工/自动采集）
   c. 执行检验/复核
   d. 电子签名确认
4. 每个步骤完成后记录到EBR步骤记录，并固化步骤快照、执行上下文、实际执行人、设备、结果和异常关联
5. 参数记录从执行快照中的参数定义生成，固化目标值、上下限、单位、数据来源和实际值
6. 所有步骤完成后提交EBR
7. 车间主管审核
8. 质量工程师审核
9. QA放行，电子签名
10. 批记录归档
11. 支持导出PDF

### 3.2 清场流程
1. 换批/换品种前执行清场检查
2. 检查上批次物料是否清除
3. 检查设备是否清洁
4. 检查标签/包材是否正确
5. 检查环境是否达标
6. 清场通过后才能开工
7. 清场记录留存

### 3.3 表单与DHR取数渲染流程
1. 工艺工程师或QA维护电子表单模板和DHR模板目录。
2. 模板按流程审核发布后启用。
3. 生产执行过程中，系统按模板生成表单实例并采集字段值。
4. 表单完成后按配置进入复核/审核/签名流程。
5. QA或系统管理员维护DHR取数来源和字段映射，明确每个模板字段来自EBR、表单、检验、称量、SCADA摘要、异常、签名、审计、追溯或包装/UDI记录。
6. 工单、批次、SN或`plan_no`收尾时，系统创建DHR渲染任务并固化模板版本和数据快照时间。
7. 系统按取数来源拉取数据、执行字段映射、聚合、格式化和必填校验。
8. 取数或渲染失败时生成错误日志并支持重试，不允许静默生成缺字段批记录。
9. 渲染成功后生成PDF/文件结果，进入QA审核和归档。
10. DHR重生成必须生成新结果版本，保留历史结果和审计追踪。

## 4. 合规要求（FDA 21 CFR Part 11）
1. EBR数据不可篡改，修改必须留痕
2. 电子签名必须绑定用户、角色、动作、对象、时间、原因
3. 签名前必须重新认证，不能仅依赖已登录会话
4. 审计日志保留至少5年
5. 批记录导出格式符合GMP要求
6. 所有关键操作必须有电子签名

## 5. 与其他模块的关系
- L2 MBR模板 → L0/L5 MBR执行上下文 → L5 EBR（模板→工单/批次执行快照→执行证据）
- L2 MBR步骤 → L0/L5 MBR执行上下文 → L5 EBR步骤记录（步骤定义→步骤快照→步骤执行）
- L2 MBR步骤参数 → L0/L5 MBR执行上下文 → L5 EBR参数记录（参数定义→参数快照→参数实际值）
- L5 称量投料 → L5 EBR（称量数据固化到EBR）
- L5 工序执行 → L5 EBR（执行数据固化到EBR）
- L5 电子表单 → L5 DHR（表单实例作为DHR取数来源）
- L5 EBR → L5 DHR（EBR步骤/参数事实作为DHR取数来源）
- L7 SCADA/环境/冷链/CIP → L5 DHR（采集摘要和证据链接作为DHR取数来源）
- L8 批次追溯 → L5 DHR（批次/SN/族谱作为DHR取数来源）
- L6 电子签名 → L5 EBR（签名绑定到EBR）
- L6 审计追踪 → L5 EBR（审计记录覆盖EBR）
- L6 异常/偏差 → L5 EBR（偏差关联到EBR）

## 6. MBR执行快照与EBR边界口径
| 对象 | 作用 | 关键约束 |
|------|------|----------|
| MBR镜像 | 已批准模板和可执行结构 | 作为新工单匹配来源，不直接作为运行中EBR的实时依据 |
| MBR执行上下文/执行快照 | 工单/批次执行依据 | 固化MBR版本、BOM版本、工艺路线版本、Phase/Step、参数、物料、设备、质控、签名和流转规则 |
| EBR头 | 批次执行证据入口 | 必须绑定工单、MBR版本、执行上下文、产品和批次 |
| EBR步骤记录 | 实际步骤执行事实 | 必须引用执行上下文和Step，并保留步骤快照，不因MBR后续改版无痕变化 |
| EBR参数记录 | 实际参数执行事实 | 必须引用Step参数快照，固化目标值、上下限、单位、数据来源和实际值 |

EBR提交、审核、放行和归档均以执行快照和EBR事实为准；DHR取数只能读取EBR、表单、检验、称量、SCADA摘要、异常、签名、审计和追溯等事实数据，不得反向修改EBR或MBR执行上下文。
