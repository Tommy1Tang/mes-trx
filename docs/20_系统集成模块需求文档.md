# 系统集成模块需求文档（L9层）
## 1. 模块概述
负责MES与外部系统的集成对接，包括SAP、PLM/文控、WMS、OA、UDI、QMS、SAP PM、培训系统等系统。所有异步集成通过Outbox模式解耦，外部系统故障不阻塞车间执行。PLM是MBR主系统，MES通过接口或受控Excel批导接收已批准MBR镜像，不在MES内重建MBR主生命周期。

**架构层：** L9 企业集成与接口运营层
**涉及表：** pro_sap_system、pro_sap_plant_ref、pro_sap_material_ref、pro_sap_bom_ref、pro_sap_bom_item_ref、pro_sap_routing_ref、pro_sap_operation_ref、pro_sap_work_center_ref、pro_sap_production_order_ref、pro_sap_plant_map、pro_sap_material_map、pro_sap_bom_map、pro_sap_bom_item_map、pro_sap_routing_map、pro_sap_operation_map、pro_sap_work_center_map、pro_sap_production_order_map、pro_interface_message、pro_report_confirmation_if、pro_inspection_result_if、pro_consumption_posting_if

## 3. 核心流程

### 3.1 SAP集成流程
1. SAP主数据每日同步到MES参考表
2. SAP生产订单实时同步到MES
3. MES创建工单并建立映射关系
4. 生产过程中投料/报工/检验数据先落MES本地事务
5. 通过Outbox异步发送到SAP
6. SAP失败进入对账补偿流程
7. 每日自动对账

### 3.2 MES创建SAP半成品生产订单流程
1. SAP MRP正常运行，半成品计划订单继续用于MRP备料和计划参考。
2. SAP将成品生产订单下发MES，MES在配套生产工作台生成`plan_no`。
3. MES根据成品订单、BOM/MBR、批量规则和产能约束生成半成品订单草稿。
4. MES在本地事务内保存创建请求，并写入Outbox事件。
5. Outbox消费者调用SAP创建生产订单接口，传递物料、数量、工厂、MRP区域、库存地点、生产版本、基本开始/完成日期和`plan_no`。
6. SAP返回正式生产订单号后，MES更新本地工单、SAP参考/映射关系和配套计划订单关系。
7. 若SAP创建失败，进入接口重试；多次失败后进入死信和对账补偿，不影响已确认的MES草稿状态。
8. 创建成功后可触发对应半成品物料单项MRP重算；若暂不触发，则等待SAP下一次MRP运行完成净需求冲抵。

### 3.3 MRP净需求冲抵口径
- MES不负责删除SAP计划订单，不在MES内替代SAP MRP。
- SAP半成品生产订单进入SAP后，作为确定供应元素参与下一次净需求计算。
- 如果数量、日期、工厂、MRP区域等匹配，原半成品计划订单可能被删除、调整数量、推迟，或产生取消/调整例外信息。
- 如果计划订单被固定、生产订单日期过晚、数量不符合批量规则或计划维度不一致，SAP可能保留计划订单并形成重复供应。
- MES必须保留`plan_no`作为业务追踪主线，并建议在SAP成品订单和半成品订单抬头增强字段中写入同一`plan_no`。
- 计划员看板应能过滤或标识“已由MES配套计划覆盖”的计划订单，避免MRP重算前误判重复供应。

### 3.4 PLM MBR接收与Excel批导流程
1. PLM完成MBR设计、版本审批、生效或冻结。
2. PLM向MES下发已批准结构化MBR；若PLM暂不能结构化输出，则授权人员上传受控Excel模板。
3. MES登记接收/导入批次、来源版本、来源文件、文件哈希和触发人。
4. MES执行结构完整性校验、引用对象校验、字典项校验、单位精度校验和映射校验。
5. 校验通过后写入`pro_mbr_*`镜像表，并建立PLM MBR ID/版本与MES镜像ID/版本映射。
6. 校验失败时生成错误明细，不允许进入可执行状态。
7. 工单下达时，MES基于当前有效MBR镜像生成执行快照，EBR执行引用快照，不实时依赖PLM。
8. PLM ECN影响运行中工单时，MES进入Safe Hold和上下文刷新机制。

### 3.5 Outbox异步解耦流程
1. 业务操作完成，本地事务提交
2. 事务内写入pro_transactional_outbox
3. Outbox Relay进程轮询outbox表
4. 发布事件到消息队列
5. 消费者处理事件，调用外部系统
6. 成功则标记outbox事件为已处理
7. 失败则重试，多次失败进入死信

### 3.6 WMS与线边仓闭环流程
1. 生产在MES按工序/MBR Step创建领料申请。
2. MES通过Outbox发送领料申请到WMS。
3. WMS执行原料库拣配和移库，可按物料批次合并多条工序需求。
4. WMS回传实际移库结果，MES保存WMS结果和原始工序需求的映射。
5. MES建立线边仓库存台账和库存流水。
6. 生产投料从MES线边仓库存扣减，单件码物料逐码扣减。
7. 生产剩余物料由MES发起退料申请，WMS执行实物退回库房。
8. WMS回传退料确认后，MES冲减线边仓库存并关闭退料单。

## 4. 关键设计原则
1. SAP主数据进入MES后形成参考表和映射表，不直接用SAP原始ID贯穿所有业务
2. 投料、报工、检验回传必须先落MES本地事务，再通过Outbox异步发送
3. SAP失败不得直接回滚车间已完成的物理动作
4. SAP失败进入对账补偿和死信处理，由业务人员或接口运维闭环
5. PLM是MBR主系统，MES是MBR执行系统；MES接收PLM已批准MBR镜像并生成执行快照，不做MBR主版本审批、生效、冻结和SOP生命周期管理
6. WMS管原料库、成品库等厂级仓储动作，MES管线边仓库存和生产使用
7. ThingsBoard管高频过程，MES管合规结论
8. MES可以创建SAP半成品生产订单，但SAP仍负责MRP净需求计算、计划订单调整和采购备料
9. `plan_no`是MES跨成品、半成品、校准品、质控品的配套追踪主线，不能用SAP单一订单号替代
10. WMS合并移库不能破坏MES工序级追溯，MES必须保留原始工序领料需求与WMS实际移库结果的映射关系
11. 设备点检、保养、维修和备品备件由SAP PM主责，MES只引用状态结果
12. 培训计划和培训记录由培训系统主责，MES只使用资质和授权结果做执行校验
