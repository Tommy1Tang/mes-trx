# 前端页面开发风格规范

> 适用范围：RuoYi Vue3 + Vite + Element Plus 的 MES 前端页面。
> 目标：让不同 AI/Agent 开发出的页面在布局、组件、交互、权限、字典、状态和验收方式上保持一致。

---

## 1. 总体原则

1. 前端页面必须沿用 RuoYi 现有后台管理风格，不做独立视觉体系。
2. MES 是生产执行系统，页面应偏操作台、配置台和审核台风格，保持紧凑、清晰、可扫描。
3. 页面开发以功能卡为最小上下文，禁止脱离功能卡自由发挥。
4. 新页面优先复用 RuoYi 已有组件、全局样式、权限指令、字典组件、分页组件、弹窗模式和下载方法。
5. 除非功能卡明确要求，禁止新增大面积营销式布局、视觉卡片墙、渐变背景、装饰图形和独立主题色。

---

## 2. 开发前加载顺序

前端 Agent 开发页面前，必须按以下顺序加载上下文：

1. `00_Blueprint.md`
2. `00_Agent_Collaboration_Rules.md`
3. `IVD_MES整体开发口径.md`
4. 本文件：`32_前端页面开发风格规范.md`
5. 当前功能卡：`30_Feature_Cards/30_FC-*.md`
6. 对应模块 Router：`10_*.md`至`22_*.md`
7. 对应接口路标：`01_Interface_Specification.md`
8. 现有参考页面，例如：
   - `ruoyi-ui-source/src/views/system/user/index.vue`
   - `ruoyi-ui-source/src/views/system/dict/index.vue`
   - `ruoyi-ui-source/src/views/tool/gen/index.vue`

若功能卡缺页面字段、按钮、状态、交互、权限或验收规则，必须先回到需求沟通补卡，再进入开发。

## 3. 技术基线

| 项 | 规范 |
|----|------|
| 前端框架 | Vue 3 |
| 构建工具 | Vite |
| UI组件 | Element Plus |
| 图标 | `@element-plus/icons-vue`，使用 RuoYi 当前写法，如`icon="Search"`、`icon="Plus"` |
| 状态管理 | Pinia，沿用现有 store 结构 |
| API请求 | 使用`@/utils/request`封装，不直接写`axios`原始调用 |
| 权限 | 使用`v-hasPermi`和`v-hasRole` |
| 字典 | 使用`proxy.useDict(...)`和`<dict-tag />` |
| 时间显示 | 使用`parseTime(...)` |
| 下载导出 | 使用`proxy.download(...)` |
| 页面根容器 | `<div class="app-container">` |

---

## 4. 目录与命名

生产模块前端页面统一放在：

```text
ruoyi-ui-source/src/views/production/{module}/
```

生产模块 API 封装统一放在：

```text
ruoyi-ui-source/src/api/production/{module}.js
```

命名规则：

| 类型 | 规则 | 示例 |
|------|------|------|
| 页面目录 | 小写短横线或业务英文名 | `dispatch-template`、`mbr-import` |
| 页面文件 | 默认列表页用`index.vue` | `index.vue` |
| 子组件 | 语义化 PascalCase | `TemplateDesigner.vue` |
| API函数 | 动词 + 业务对象 | `listDispatchTemplate`、`getDispatchTemplate` |
| 权限标识 | `production:模块:动作` | `production:dispatch:add` |

## 5. 标准页面结构

### 5.1 列表维护页

适用于主数据、规则配置、接口消息、模板列表等页面。

固定结构：

1. 查询区：`el-form inline`
2. 工具栏：`el-row class="mb8"`
3. 表格：`el-table`
4. 分页：`<pagination />`
5. 新增/编辑：`el-dialog`
6. 详情/预览：优先`el-drawer`或只读`el-dialog`

查询区规则：

- 常用条件 3 到 6 个。
- 输入框宽度默认 240px。
- 日期范围宽度默认 308px。
- 查询按钮顺序固定为：`搜索`、`重置`。
- 支持回车查询：`@keyup.enter="handleQuery"`。

工具栏按钮顺序：

```text
新增 → 修改 → 删除/停用 → 导入 → 导出 → 发布/启用/停用等业务动作 → right-toolbar
```

表格规则：

- 第一列需要批量操作时使用 selection。
- 编码、名称、批号、版本等长文本使用`:show-overflow-tooltip="true"`。
- 状态列优先用`dict-tag`；需要交互开关时才用`el-switch`。
- 时间列宽度默认 160px 或 180px。
- 操作列使用`el-button link type="primary"`，图标按钮必须加`el-tooltip`。

### 5.2 树 + 列表页

适用于组织、部门、工厂车间、模板目录等层级对象。

固定结构：

- 左侧：树或目录过滤区。
- 右侧：查询区、工具栏、表格、分页。
- 沿用`splitpanes`或 RuoYi 现有左右结构。
- 左侧宽度默认 16% 到 24%，不得做复杂视觉卡片。

### 5.3 配置设计页

适用于派工单模板、DHR模板、电子表单、MBR结构预览等。

推荐结构：

- 顶部：基础信息和版本状态。
- 左侧：分区/字段/节点树。
- 中间：配置明细或预览区域。
- 右侧：属性编辑区，可用 drawer 或固定窄面板。

约束：

- 配置页仍然使用 Element Plus 表单、表格、Tabs、Collapse，不做自由画布式 UI，除非功能卡明确要求。
- 模板预览必须区分“配置态”和“只读预览态”。
- 发布后的模板版本不允许直接编辑，应走复制版本或新版本流程。

### 5.4 执行工作台页

适用于派工执行、称量投料、EBR步骤执行、异常处理等现场操作。

推荐结构：

- 顶部：工单/批次/物料/工序/状态摘要。
- 主区：当前步骤、待执行任务、扫码/称量/参数采集入口。
- 侧区或底部：执行历史、异常、审计、提示信息。

约束：

- 关键动作按钮必须清楚区分主次，例如`开始`、`提交`、`复核`、`完成`。
- 危险动作必须二次确认，例如`作废`、`驳回`、`强制放行`。
- 涉及电子签名的动作不得只做普通确认弹窗，必须预留签名弹窗入口。

## 6. 表单规范

| 场景 | 规范 |
|------|------|
| 新增/编辑弹窗 | 使用`el-dialog`，宽度默认 500px/600px/800px |
| 详情/预览 | 使用只读`el-dialog`或`el-drawer` |
| 标签宽度 | 常规 80px/100px；长字段 120px |
| 两列表单 | 使用`el-row` + `el-col :span="12"` |
| 必填校验 | 写入`rules`，消息使用“不能为空” |
| 长文本 | 使用`el-input type="textarea"` |
| 数量/重量/浓度 | 使用`el-input-number`或受控数字输入 |
| 日期时间 | 使用`el-date-picker`，统一`value-format` |

禁止：

- 前端只靠 placeholder 表达业务规则。
- 必填字段只在后端校验、前端没有规则。
- 一个弹窗塞入过多区域导致滚动困难；复杂对象应拆成 Tabs 或子页面。

## 7. 按钮与动作

### 7.1 常用按钮

| 动作 | 类型 | 图标 | 说明 |
|------|------|------|------|
| 搜索 | primary | Search | 查询区 |
| 重置 | default | Refresh | 查询区 |
| 新增 | primary plain | Plus | 工具栏 |
| 修改 | success plain | Edit | 工具栏 |
| 删除 | danger plain | Delete | 工具栏 |
| 导入 | info plain | Upload | 工具栏 |
| 导出 | warning plain | Download | 工具栏 |
| 查看 | link primary | View | 行操作 |
| 配置 | link primary | Setting/Operation | 行操作 |
| 预览 | link primary | View | 行操作 |
| 发布 | primary/plain | Promotion/Check | 业务动作 |
| 停用 | warning/danger | Close/Remove | 业务动作 |

### 7.2 操作确认

以下动作必须二次确认：

- 删除、作废、停用
- 发布、冻结、解锁
- 驳回、强制关闭、强制放行
- 触发外部接口重试、补偿、死信重投

确认文案必须包含业务对象，例如：

```text
是否确认停用模板编码为“xxx”的派工单模板？
```

## 8. 字典、状态与标签

1. 状态字段必须优先使用字典，不允许前端硬编码中文枚举。
2. 列表状态显示优先使用`<dict-tag />`。
3. 状态流转按钮必须根据当前状态控制显示和禁用。
4. 常见状态语义：

| 状态 | 展示口径 |
|------|----------|
| 草稿 | 可编辑、不可执行 |
| 已发布 | 可引用、不可直接修改 |
| 停用 | 不可新引用，历史可追溯 |
| 执行中 | 可继续操作 |
| 待审核 | 禁止修改关键执行数据 |
| 已完成 | 只读 |
| 已作废 | 只读且保留审计 |

---

## 9. 权限规范

按钮必须绑定权限，不允许只靠后端拦截。

权限示例：

```vue
<el-button
  type="primary"
  plain
  icon="Plus"
  @click="handleAdd"
  v-hasPermi="['production:dispatch:add']"
>新增</el-button>
```

常用动作权限：

| 动作 | 后缀 |
|------|------|
| 查询 | `query` |
| 新增 | `add` |
| 修改 | `edit` |
| 删除 | `remove` |
| 导入 | `import` |
| 导出 | `export` |
| 发布 | `publish` |
| 停用 | `disable` |
| 审核 | `audit` |
| 打印 | `print` |

---

## 10. API调用规范

API文件必须使用 RuoYi request 封装：

```js
import request from '@/utils/request'

export function listXxx(query) {
  return request({
    url: '/production/xxx/list',
    method: 'get',
    params: query
  })
}
```

约束：

- 不直接写`axios`。
- 不硬编码完整域名。
- 查询接口用`params`。
- 新增/修改用`data`。
- 删除接口遵循 RuoYi 当前路径风格。
- 导出使用`proxy.download(...)`。
- 接口路径必须与`00_Blueprint.md`和`01_Interface_Specification.md`一致。

## 11. 数据展示规范

| 数据类型 | 展示规则 |
|----------|----------|
| 编码/批号/订单号 | 表格居中，超长 tooltip |
| 名称/描述 | 可左对齐，超长 tooltip |
| 数量/重量/体积 | 显示单位，必要时保留小数位 |
| 百分比 | 明确显示`%` |
| 日期时间 | 使用`parseTime` |
| 人员 | 显示姓名，必要时附工号 |
| 外部系统单号 | 显示来源系统和单号 |
| 审计/异常原因 | 使用详情弹窗或 drawer，避免挤在表格内 |

## 12. MES业务特有页面规则

### 12.1 受控数据

以下数据默认不做物理删除：

- 已发布模板
- 已被工单引用的数据
- 批记录、称量、投料、检验、审计、签名记录
- 外部接口消息和补偿记录

页面动作应使用`停用`、`作废`、`冻结`、`关闭`等受控动作。

### 12.2 电子签名

涉及以下动作时，页面必须预留电子签名交互：

- 审核、复核、放行
- 驳回、作废、强制关闭
- 关键参数修改
- 异常关闭
- 批记录归档

### 12.3 审计追踪

关键页面应提供审计入口：

- 行操作增加`审计`或详情页 Tabs 中增加`审计记录`。
- 审计只读展示，不能编辑。
- 审计字段至少包括动作、对象、修改前、修改后、操作人、时间、原因。

---

## 13. 样式约束

1. 页面根节点使用`app-container`。
2. 工具栏使用`el-row :gutter="10" class="mb8"`。
3. 优先使用 RuoYi 全局样式，例如`mb8`、`small-padding`、`fixed-width`、`link-type`。
4. 新增样式必须`scoped`，禁止污染全局。
5. 不新增大面积自定义主题色。
6. 不使用渐变背景、装饰图形、营销式 hero 区域。
7. 不把页面区块层层套卡片；只有重复条目、弹窗内容、预览对象可以使用轻量卡片。
8. 表格、按钮、弹窗、查询区的间距沿用现有 RuoYi 页面。

---

## 14. 响应式与可用性

1. 至少保证 1366px 宽度下无明显错位。
2. 窄屏时查询区允许自然换行。
3. 表格列过多时优先使用列显隐、详情 drawer 或横向滚动，不强行压缩文字。
4. 按钮文字不得溢出按钮。
5. 重要操作不能只靠颜色区分。
6. 图标按钮必须有 tooltip。

---

## 15. 前端开发交付检查清单

开发完成后，前端 Agent 必须自查：

- 页面是否使用`app-container`。
- 查询区、工具栏、表格、分页、弹窗是否沿用 RuoYi 模式。
- 按钮是否绑定`v-hasPermi`。
- 状态是否使用字典或`dict-tag`。
- 新增/编辑表单是否有必填规则。
- 删除/停用/发布/驳回等动作是否二次确认。
- 导出是否使用`proxy.download`。
- API是否使用`@/utils/request`封装。
- 是否存在硬编码中文状态枚举。
- 是否存在无必要自定义颜色、卡片、装饰样式。
- 是否检查列表页、新增弹窗、编辑弹窗、详情/预览、空数据和校验失败状态。

## 17. 禁止事项

- 禁止脱离 RuoYi 现有风格重做页面视觉。
- 禁止为普通后台页面设计 landing page、hero、营销式介绍区。
- 禁止硬编码状态、枚举、接口地址和权限绕过。
- 禁止用前端假数据冒充接口联调完成。
- 禁止未读功能卡就开发页面。
- 禁止功能卡未确认时直接实现复杂交互。
- 禁止为受控生产数据提供无审计的物理删除入口。
