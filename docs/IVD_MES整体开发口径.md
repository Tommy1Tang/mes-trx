# IVD MES 整体开发口径

## 1. 定位

本口径基于现有 `MES系统基础表清单_按优先级.md` 和逐字段数据字典制定，不修改原表结构。

IVD MES 的定位不是普通“工单 + 报工系统”，而是面向试剂生产的受控制造执行平台，核心目标是：

- 把 SAP/PLM/文控系统下发的计划、物料、BOM、工艺、文件和质量要求转化为车间可执行、可防错、可追溯的 MBR/EBR/DHR。
- 对配液、称量、线边仓、领退料、孵育、灌装、冻干、包装、清洗、冷链、环境和公用工程过程形成电子证据链。
- 通过规则联锁、电子签名、审计追踪、异常偏差、批记录审核满足 GMP、ISO 13485、21 CFR Part 11 等受控生产要求。
- 通过 Outbox、幂等、死信、对账补偿保护车间执行，不让 SAP/WMS/ThingsBoard 等外部系统故障反向阻塞生产。

一句话口径：MES 管“受控执行、现场防错、线边仓执行、MBR执行镜像、批记录证据、质量闭环和系统集成缓冲”，不替代 ERP、PLM/文控、WMS、SCADA、QMS、SAP PM、培训系统的系统边界。

## 2. 系统边界

| 系统 | 主责 | MES 对接口径 | MES 不应承担 |
|---|---|---|---|
| SAP ERP | 销售、计划、采购、财务、成本、库存账、主数据源头 | 接收生产订单、物料、BOM、Routing、工厂、库存批次等参考数据；回传报工、投料、检验结果 | 不在 MES 内做财务库存总账、MRP、采购结算和成本核算 |
| PLM/文控系统 | 产品设计、研发配方、工艺文件、SOP、文档版本、变更源头 | 接收受控配方、文件、ECN、版本和适用范围；转化为 MES 可执行 MBR；MES 仅保存 SOP 引用、版本号、链接和工序绑定 | 不在 MES 内替代研发设计、文档生命周期、文档审批和设计评审 |
| WMS/外部仓储系统 | 原料库、成品库等厂级仓储作业、库内库存、拣配、上架、移库、盘点 | 接收可投料批次、库位、发料结果；回传生产领用、退料、成品入库请求；线边仓由 MES 自管 | 不在 MES 内重做原料库/成品库的仓储策略、库内路径优化和全量库存账 |
| SAP PM | 设备点检、保养、维修、备品备件和设备资产维护 | MES 引用设备可用状态、维保到期状态、维修状态、设备锁定/解锁结果 | 不在 MES 内自建设备维保维修工单、保养计划和备品备件库存 |
| 培训系统 | 培训计划、培训需求、培训记录、培训结果 | MES 接收或维护人员资质、岗位/工序/设备授权和有效期，用于执行前资质校验 | 不在 MES 内管理完整培训计划、培训记录和培训过程 |
| ThingsBoard/SCADA/PLC | 高频采集、设备状态、实时报警、边缘联锁 | 保存设备映射、点位模型、关键采集结论、告警事件、过程摘要 | 不在 MES 主库保存高频原始时序数据，不用 MES 替代 PLC 安全控制 |
| QMS/eQMS | 偏差、CAPA、变更、培训、投诉、放行流程 | MES 记录现场异常、偏差来源、批记录证据；必要时推送 QMS 建立正式质量流程 | 不在 MES 内完整替代企业级 CAPA、供应商质量和投诉管理 |

## 3. 数据分层开发口径

现有表可按 `L0-L10` 架构层推进开发，但开发时要区分“业务建模层”和“运行时保护层”。

| 层级 | 开发口径 | 关键关注 |
|---|---|---|
| L0 运行时韧性与架构支撑层 | 先设计，贯穿所有模块 | Outbox、幂等、防重复提交、死信、对账补偿、MBR 上下文预编译 |
| L1 主数据与资源基础层 | 第一批落地 | 工厂、车间、产线、工作中心、人员、设备、物料、班次、仓库、环境区域 |
| L2 产品、工艺与 MBR 模板层 | IVD MES 的核心建模层 | BOM、Routing、MBR、Phase、Step、参数、物料、设备、质控项、返工和动态参数 |
| L3 执行规则、联锁与变更控制层 | 与 L2 同步设计，分步上线 | 防错规则、联锁规则、ECN、版本发布、差异对比、Safe Hold |
| L4 计划订单与车间调度层 | 承接 SAP 订单后上线 | 工单、组件、工序实例、排产、派工 |
| L5 现场执行、称量与电子批记录层 | 第一条产线试点的主战场 | 报工、投料、称量、清场、过程会话、EBR 步骤和参数固化 |
| L6 质量异常与合规审计层 | 与执行层同步上线 | 不良、检验、异常、处置、电子签名、审计追踪 |
| L7 OT/SCADA、环境公用与清洗冷链层 | 按设备接入成熟度渐进上线 | ThingsBoard 映射、采集点位、环境、纯化水、冷链、CIP/SIP、OEE |
| L8 追溯仓储与批次族谱层 | 随投料和成品流转同步增强 | 批次、序列号、WIP、成品、批次族谱、正反向追溯 |
| L9 企业集成与接口运营层 | 接口先异步后闭环 | SAP/WMS/PLM 映射、接口消息、投料过账、报工确认、检验回传 |
| L10 仿真分析与持续优化层 | 不阻塞一期上线 | 工艺仿真、产能瓶颈、节拍优化、质量风险分析 |

## 4. IVD 工艺开发口径

### 4.1 配液与称量

配液是 IVD MES 的优先试点场景。开发时应以 MBR Step 为最小执行单元，而不是只按宏观工序报工。

应实现：

- 物料扫码、批次校验、有效期校验、状态校验。
- 电子天平点检、校准状态确认、称量目标值/实际值/允差自动判定。
- 称量异常、复核、驳回、补称、重称全过程审计。
- 搅拌转速、温度、时间、重量、pH、电导率等关键参数固化到 EBR。

对应表层：L2、L3、L5、L6、L7、L8。

### 4.2 孵育、反应与过程监控

孵育和反应过程要以“过程会话 + 采集摘要 + EBR 参数记录”表达，不建议把每秒级数据写入 MES 主库。

应实现：

- MES 下发或确认过程开始、暂停、结束。
- ThingsBoard/SCADA 记录高频曲线。
- MES 固化最大值、最小值、均值、超限时长、曲线链接和判定结果。
- 超限自动生成异常或待复核状态。

对应表层：L0、L3、L5、L6、L7。

### 4.3 灌装、包装与清场防混淆

灌装包装重点不是“多录几张报表”，而是控制换批、换品种、标签、瓶子、盖子、说明书等防混淆风险。

应实现：

- 工单、物料、标签、包材、设备状态一致性校验。
- 首件、尾件、清场、换线确认。
- PLC 状态、产量、停机原因、OEE 采集。
- 条码/视觉结果统一进入防错记录。

对应表层：L3、L4、L5、L6、L7、L8。

### 4.4 冻干

冻干通常具有长周期、强曲线、强参数放行特征。现有表结构可先用 MBR Step、过程监控会话、采集摘要和 EBR 参数记录承接。

应实现：

- 冻干程序版本、设备、批次、装载信息确认。
- 搁板温度、真空度、时间段、阶段切换等参数摘要固化。
- 异常报警与批记录关联。

若后续冻干程序需要 MES 深度建模，可在 L2/L7 下再补充专用冻干程序模板和冻干曲线结果表。

### 4.5 CIP/SIP 与环境/公用工程

清洗、灭菌、环境和纯化水不是附属报表，而是批放行证据的一部分。

应实现：

- 清洗/灭菌周期记录、参数摘要、复核、放行。
- 洁净区温湿度、压差、粒子等关键环境证据固化。
- 纯化水电导率、TOC、水温、流速等关键质量数据固化。
- 冷库、冰箱、运输箱温度异常与物料批次风险关联。

对应表层：L5、L6、L7、L8。

## 5. 合规开发口径

### 5.1 电子记录

所有用于批放行、偏差调查、追溯召回和监管检查的电子数据，都应按电子记录管理。

开发要求：

- 关键业务数据只能通过受控流程新增、修改、作废。
- 修改必须保留修改前、修改后、修改人、修改时间、修改原因。
- 关键记录要能导出为人可读格式，并能保持内容和含义不丢失。
- 电子记录的归档、检索、留存和权限控制必须在系统设计阶段定义。

落地表：`pro_audit_trail`、`pro_e_signature_record`、`pro_ebr_header`、`pro_ebr_step_record`、`pro_ebr_param_record`。

### 5.2 电子签名

电子签名不只是登录密码确认，而是对具体业务动作的责任确认。

开发要求：

- 执行、复核、审核、放行、驳回、偏差关闭应区分签名含义。
- 签名必须绑定用户、角色、动作、对象、时间、原因和签名结果。
- 签名前应重新认证，不能仅依赖已登录会话。
- 签名后记录不得被无痕修改。

落地表：`pro_e_signature_record`、`pro_audit_trail`。

### 5.3 审计追踪

审计追踪应优先覆盖 MBR、EBR、称量、投料、检验、异常、放行、接口补偿等高风险对象。

开发要求：

- 审计日志应由统一组件写入，不能依赖每个业务页面手写。
- 对关键记录的新增、修改、删除、作废、复核、放行均要留痕。
- 审计记录原则上只追加，不允许业务人员修改。

落地表：`pro_audit_trail`。

### 5.4 DHR/批记录模板取数与渲染

DHR/批记录模板属于 MES 输出层，负责从 EBR 和相关业务数据中取数、组装、渲染、审核和归档，不反向驱动生产，也不能覆盖 EBR 原始事实。

开发要求：

- DHR模板应支持产品、MBR版本、批次/SN、`plan_no`等维度配置。
- 取数来源应覆盖 EBR步骤记录、EBR参数记录、称量、投料、检验、SCADA采集摘要、环境/纯化水/冷链/CIP记录、异常偏差、电子签名、审计追踪、批次/序列号追溯、标签/UDI/包装记录。
- 字段映射应支持业务字段、聚合规则、格式化规则、缺失值处理和必填校验。
- 渲染任务应记录模板版本、业务对象、数据快照时间、生成状态、失败原因和重试记录。
- 批记录重生成必须保留历史结果、重生成原因、触发人、前后文件版本和审计追踪。

建议补充：`pro_dhr_data_source`、`pro_dhr_field_mapping`、`pro_dhr_render_task`、`pro_dhr_render_result`、`pro_dhr_render_log`。

## 6. 集成开发口径

### 6.1 SAP 集成

SAP 是计划和账务系统，MES 是执行和证据系统。两者之间必须异步解耦。

开发要求：

- SAP 主数据进入 MES 后应形成参考表和映射表，不直接用 SAP 原始 ID 贯穿所有业务。
- 投料、报工、检验回传必须先落 MES 本地事务，再通过 Outbox 异步发送。
- SAP 失败不得直接回滚车间已经完成的物理动作。
- SAP 失败进入对账补偿和死信处理，由业务人员或接口运维闭环。

落地表：L0、L9。

### 6.2 PLM 与 MBR 接收

PLM 是 MBR 主系统，负责 SOP 拆解、MBR 设计、版本审批、生效、冻结和变更控制。MES 是 MBR 执行系统，只接收 PLM 已批准的结构化 MBR 镜像，并在工单下达时生成执行快照。

开发要求：

- PLM 下发的是已批准的结构化 MBR，包括工序、工步、生产指令、参数、物料、设备、质控项、SOP 引用和适用范围。
- MES 不做 MBR 主版本审批、生效和冻结，`pro_mbr_*` 表在 MES 中定位为 PLM MBR 镜像和执行结构。
- MES 接收 PLM MBR 后必须做结构完整性校验，例如工序、工步、参数、物料、设备、质控项、字典项和必填规则是否完整。
- PLM 暂时无法结构化输出时，MES 可提供 Excel 批导作为受控补充入口；Excel 批导必须保留文件、哈希、导入人、校验结果、审核状态和审计追踪。
- 工单下达时，MES 必须基于当前有效的 PLM MBR 镜像生成工单/批次执行快照，EBR 执行引用快照，不实时依赖 PLM。
- PLM ECN 影响运行中工单时，MES 进入 Safe Hold 和上下文刷新机制；MES 只执行 PLM 变更结果，不替代 PLM 审批。

落地表：`pro_mbr_header`、`pro_mbr_version`、`pro_mbr_phase`、`pro_mbr_step`、`pro_mbr_step_parameter`、`pro_mbr_step_material`、`pro_mbr_step_equipment`、`pro_mbr_step_quality`、`pro_mbr_execution_context`、`pro_mbr_context_refresh_log`。

建议补充：`pro_mbr_import_batch`、`pro_mbr_import_item`、`pro_mbr_import_validate_log`、`pro_mbr_import_error`、`pro_mbr_source_file`、`pro_mbr_source_map`。

### 6.3 WMS 与线边仓

WMS/外部仓储系统管原料库、成品库等厂级仓储动作，MES 管车间线边仓和生产使用。未来线边仓不由 WMS 管理，因此线边仓库存、领料、分发、退料、盘点和预警应作为 MES 正式业务能力。

开发要求：

- MES 获取外部仓储系统中的可用库存、批次、库位、发料结果。
- 生产在 MES 按工序创建领料单，领料需求应关联工单、工序、MBR Step、物料、需求数量和需求批次规则。
- MES 将领料申请发送给 WMS，WMS 负责库房侧拣配和移库；相同物料、相同批次可以由 WMS 合并后一次移库到线边仓。
- WMS 回传实际移库结果后，MES 需要保存 WMS 合并结果与原始工序领料需求的映射关系，避免后续追溯丢失工序维度。
- 物料进入线边仓后，线边仓库存台账、库存流水、盘点、预警由 MES 管理。
- MES 线边仓投料需要同时支持单件码和非单件码。单件码物料逐码扫描、逐码追踪；非单件码物料按批次和数量管理。
- MES 投料以现场扫码、称量、领用和消耗记录为最终执行证据。
- 生产剩余物料由 MES 发起退料申请并传给 WMS，库房完成退料后回传确认，MES 冲减线边仓库存并形成闭环。
- 生产需定期对线边仓进行盘库清理，盘点差异必须记录原因、复核和库存调整流水。
- 报废、成品入库请求应通过接口事件异步传递给 WMS/SAP。

落地表：L8、L9、L0。

### 6.4 ThingsBoard/SCADA 集成

ThingsBoard/SCADA 管高频过程，MES 管合规结论。

开发要求：

- 原始高频遥测保留在 ThingsBoard/时序库。
- MES 只保存与工单、批次、步骤、放行相关的关键值、摘要、告警和曲线引用。
- 毫秒级联锁尽量在 PLC/边缘侧完成，MES 负责规则配置、放行判定和证据固化。

落地表：L7、L5、L6、L0。

## 7. 一期建议开发范围

一期不建议直接铺满 147 张表，而应围绕“一个受控产品 + 一条典型产线 + 一个完整批记录闭环”建设最小合规闭环。

建议一期范围：

- 主数据：工厂、车间、产线、工作中心、人员、设备、物料、班次、仓库。
- MBR接收：从 PLM 接收已批准结构化 MBR，必要时通过受控 Excel 批导导入，并完成结构校验和镜像落库。
- 工艺执行结构：BOM、Routing、MBR Header/Version/Phase/Step/Parameter/Material/Equipment/Quality。
- 工单执行：生产订单、组件、工序实例、派工、工序执行、报工、投料。
- 线边仓：线边仓库存、库存流水、生产领料、物料分发、生产退料、盘点和预警。
- 配液称量：电子天平点检、称量记录、防错校验、称量审计。
- EBR：批记录头、步骤记录、参数记录、批记录审核。
- DHR模板：配置批记录模板、章节、取数来源、字段映射、渲染任务、生成结果和重生成留痕。
- 合规：电子签名、审计追踪、异常记录。
- 集成：SAP 订单/BOM/物料/工艺参考数据同步，报工/投料异步回传。
- OT：ThingsBoard 设备映射、点位、关键采集值、告警事件、过程摘要。
- 运行时：Outbox、幂等、死信、对账补偿、MBR 执行上下文。

一期暂缓：

- 深度仿真优化。
- 全量 OEE 高级分析。
- 全厂冷链矩阵。
- 全量 CIP/SIP 自动放行。
- 完整委外工艺。
- 多产品复杂替代工艺全覆盖。

## 8. AI Coding 上下文加载口径

后续让 AI 开发时，采用 Absolute Progressive Loading。不要一次加载全部模块文档或全部 147 张表，应先定位任务，再加载最小事实集：

1. 固定启动上下文：`00_Blueprint.md`、`00_Agent_Collaboration_Rules.md`、`IVD_MES整体开发口径.md`。
2. 业务定位：读取对应模块Router（`10_*.md`至`22_*.md`）和`30_Feature_Card_Index.md`。
3. 开发事实：按`FC-*`或`REQ-*`只读取相关`30_Feature_Cards/30_FC-*.md`。
4. 落地补充：再按功能卡声明的表、接口和治理规范精确读取字段字典、接口规范和数据模型治理文件。

## 9. 关键原则

- MES 的第一性原理是“受控执行”，不是“多录数据”。
- MBR 是执行模板，EBR 是实际证据，二者必须版本绑定。
- 现场物理动作优先保证连续执行，外部系统通过 Outbox 和补偿机制最终一致。
- 高频数据留在 OT/时序平台，MES 固化合规需要的结果、摘要、告警和证据链接。
- 所有影响批放行的数据都必须能解释来源、责任人、时间、版本和修改历史。
- 一期以配液称量和电子批记录闭环作为 MVP，比泛泛铺开所有模块更稳。
