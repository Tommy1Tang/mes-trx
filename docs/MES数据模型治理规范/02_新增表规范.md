# 新增表规范

## 新增表前判断

新增表前先回答 5 个问题：

1. 这个对象是否已有表可以承载？
2. 它是主数据、业务单据、明细、日志、映射、接口消息还是配置？
3. 它是否需要独立生命周期？
4. 它是否会被多个模块复用？
5. 它是否需要独立权限、查询、导入导出或审批？

如果只是已有业务对象的一个属性，优先新增字段。

如果有独立生命周期、独立状态、独立明细或会被多个模块引用，可以新增表。

## 命名规范

- 表名使用小写下划线。
- 生产模块表统一使用 `pro_` 前缀。
- 主数据表建议使用 `_master` 后缀。
- 映射表建议使用 `_map` 后缀。
- 明细表建议使用 `_item` 后缀。
- 日志表建议使用 `_log` 后缀。
- 接口表建议使用 `_if` 后缀。
- 关系表建议使用业务对象组合命名，如 `pro_wc_equipment`。

## 主键规范

- 每张表必须有且只有一个主键。
- 主键类型统一建议 `bigint(20)`。
- 主键字段命名优先使用业务对象名加 `_id`。
- 多对多关系表可以使用独立 `id`，但更推荐使用明确业务名，如 `wc_equipment_id`。
- 业务编码不能替代主键，只能作为唯一键。

## 标准字段

除特殊接口临时表外，建议包含：

| 字段 | 说明 |
|---|---|
| `create_by` | 创建人 |
| `create_time` | 创建时间 |
| `update_by` | 更新人 |
| `update_time` | 更新时间 |
| `del_flag` | 逻辑删除标识 |
| `remark` | 备注 |

## 状态字段

业务对象有生命周期时必须设计状态字段：

- 字段命名：`xxx_status`
- 类型：`varchar(20)`
- 必填：`Y`
- 必须配置 `dict_code`

## 唯一键建议

常见唯一键：

- 主数据：`code`
- 工厂隔离主数据：`plant_id + code`
- 版本对象：`对象 + version`
- 明细行：`header_id + line_no` 或 `header_id + item_no`
- 映射表：外部参考 ID 或外部参考 ID + 本地对象 ID

## 外键规范

- 外键字段命名优先使用被引用表主键名。
- `foreign_key = Y` 时必须填写 `foreign_key_ref`。
- `foreign_key_ref` 格式：`表名.字段名`。
- 泛型外键必须说明约束方式，强监管追溯场景优先拆成明确外键。

## 优先级分层

新增表必须归入一个优先级：

- `P0`：核心运行层。
- `P1`：增强协同层。
- `P2`：高级追溯与接口运营层。
- `P0+`：需求驱动补充核心表。
