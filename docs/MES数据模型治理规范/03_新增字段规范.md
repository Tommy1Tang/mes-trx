# 新增字段规范

## 新增字段前判断

新增字段前先判断：

- 是否已有字段可以表达？
- 是否属于当前表对应的业务对象？
- 是否会引入跨模块强耦合？
- 是否只是查询展示字段？
- 是否可以通过关联表查询得到？

如果字段只是冗余展示字段，必须说明冗余原因。

## 命名规范

| 类型 | 命名 |
|---|---|
| 编码 | `xxx_code` |
| 名称 | `xxx_name` |
| 类型 | `xxx_type` |
| 状态 | `xxx_status` |
| 标识 | `xxx_flag` |
| 数量 | `xxx_qty` |
| 单位 | `xxx_uom` |
| 时间 | `xxx_time` |
| 日期 | `xxx_date` |
| 版本 | `xxx_version` |
| 说明 | `xxx_desc` |
| 原因 | `xxx_reason` |
| 结果 | `xxx_result` |

## 字段说明规范

`field_comment` 必须是普通人能看懂的中文描述。

推荐：

- `计划开始时间`
- `组件物料ID`
- `是否批次管理`
- `检验判定`

不推荐：

- `planned_start时间`
- `component_materialID`
- `batch_managed标识`
- `result_judgement`

允许保留常见缩写：

- `ID`
- `SAP`
- `BOM`
- `UDI`

## 类型规范

| 场景 | 类型建议 |
|---|---|
| 主键/外键 | `bigint` |
| 编码 | `varchar(64)` |
| 名称 | `varchar(128)` |
| 状态 | `varchar(20)` |
| 类型 | `varchar(32)` |
| 标识 | `char(1)` |
| 数量 | `numeric(18,6)` |
| 工时 | `numeric(18,2)` |
| 日期时间 | `timestamp` |
| 纯日期 | `date` |
| 班次内时间 | `time` |
| 备注 | `varchar(500)` |
| 长描述 | `varchar(1000)` |
| 长文本 | `text` |
| JSON快照/载荷 | `jsonb` |

说明：

- 当前数据库默认按 PostgreSQL 落地。
- 生成建表 SQL 时必须以 `MES系统基础表逐字段数据字典_按优先级_pgsql.csv` 为准。
- 通用字段字典中的 `datetime`、`decimal`、`int` 只作为逻辑类型参考，落地 PostgreSQL 时分别转换为 `timestamp`、`numeric`、`integer`。
- 上下文快照、事件载荷、响应快照、步骤快照等结构化内容优先使用 `jsonb`。

## 必填规范

通常必填：

- 主键
- 业务编码
- 业务名称
- 状态字段
- 核心外键
- 创建人
- 创建时间
- 逻辑删除标识

通常可空：

- 备注
- 更新时间
- 更新人
- 附件地址
- 审核意见
- 结束时间
- 非强制外键

## 默认值规范

| 字段类型 | 默认值建议 |
|---|---|
| `create_time` | `CURRENT_TIMESTAMP` |
| `del_flag` | `'0'` |
| `xxx_flag` | `N` |
| 数量字段 | `0` |
| 状态字段 | 按业务字典确定 |

## 字典编码规范

以下字段必须配置 `dict_code`：

- `xxx_status`
- `xxx_type`
- `xxx_flag`
- `xxx_reason`
- `xxx_result`
- `xxx_judgement`
- `xxx_stage`
- `direction`
- `severity_level`
- `priority_level`

## 外键字段规范

外键字段必须满足：

- `foreign_key = Y`
- `foreign_key_ref` 非空
- 引用目标字段存在
- 外键字段类型与目标主键类型一致

## 禁止事项

- 不要把业务编码字段设为主键。
- 不要把外键字段设为主键，除非明确采用复合主键；当前模型默认不使用复合主键。
- 不要新增含义模糊的字段，如 `value1`、`flag1`、`type1`。
- 不要新增没有字典编码的状态或类型字段。
- 不要在 PostgreSQL DDL 中使用 MySQL 方言类型，如 `auto_increment`、`tinyint`、`datetime`。
