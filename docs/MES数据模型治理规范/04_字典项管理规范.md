# 字典项管理规范

## 适用范围

凡是字段值来自固定枚举、状态流转、类型分类、原因、判定结果，都应使用 `dict_code` 管理。

## 必须使用字典的字段

- 状态：`xxx_status`
- 类型：`xxx_type`
- 标识：`xxx_flag`
- 原因：`xxx_reason`
- 结果：`xxx_result`
- 判定：`xxx_judgement`
- 阶段：`xxx_stage`
- 方向：`direction`
- 严重等级：`severity_level`
- 优先级：`priority_level`

## 命名规范

字典编码使用小写下划线：

- 系统通用：`sys_yes_no`、`sys_del_flag`
- MES 专用：`mes_业务对象_字段含义`

示例：

- `mes_order_status`
- `mes_schedule_status`
- `mes_inspection_judgement`
- `mes_exception_status`
- `mes_operation_resource_type`

## 字典值规范

建议字典值使用稳定代码，不直接使用中文。

示例：

| 字典编码 | 字典值 | 显示名称 |
|---|---|---|
| `sys_yes_no` | `Y` | 是 |
| `sys_yes_no` | `N` | 否 |
| `sys_del_flag` | `0` | 存在 |
| `sys_del_flag` | `2` | 删除 |

## 状态字段建议

状态字段建议使用业务语义明确的值：

- `DRAFT`
- `PENDING`
- `ACTIVE`
- `RELEASED`
- `RUNNING`
- `COMPLETED`
- `CLOSED`
- `CANCELLED`

如果项目已有若依通用状态，也可以使用 `0/1`，但必须在字典中说明含义。

## 字典变更规则

新增字典项时必须记录：

- 字典编码
- 字典名称
- 字典值
- 显示名称
- 排序号
- 是否默认
- 适用字段
- 变更原因

## AI Coding 提示

当 AI 新增以下字段时，必须同时检查或补充 `dict_code`：

- 包含 `status`
- 包含 `type`
- 包含 `flag`
- 包含 `reason`
- 包含 `result`
- 包含 `judgement`
- 包含 `stage`
- 字段名为 `direction`
- 字段名为 `severity_level`
- 字段名为 `priority_level`
