# 校验规则清单

## 硬性校验

每次修改数据字典后必须校验：

- 每张表必须有且只有一个主键。
- 表内不能有重复字段名。
- 表内不能有重复字段顺序。
- `foreign_key = Y` 时，`foreign_key_ref` 必须非空。
- `foreign_key_ref` 指向的表和字段必须存在。
- 主键字段必须 `nullable = N`。
- 主键字段建议为 `bigint`。
- `field_name`、`field_comment`、`data_type`、`nullable` 不允许为空。
- PostgreSQL 建表落地必须使用 `MES系统基础表逐字段数据字典_按优先级_pgsql.csv`。

## 字典校验

以下字段必须有 `dict_code`：

- `xxx_status`
- `xxx_type`
- `xxx_flag`
- `xxx_reason`
- `xxx_result`
- `xxx_judgement`
- `xxx_stage`
- `direction`
- `severity_level`
- `priority_level`

## 字段说明校验

`field_comment` 必须是通俗中文描述。

允许保留：

- `ID`
- `SAP`
- `BOM`
- `UDI`

不允许出现：

- 未解释的英文单词
- 下划线
- 机械翻译，如 `actual_start时间`
- 混合表达，如 `component_materialID`

## 类型校验

- 数量字段应为 `numeric`。
- 金额字段应为 `numeric`。
- 工时字段应为 `numeric`。
- 主键和外键应为 `bigint`。
- 标识字段应为 `char(1)`。
- 时间字段应为 `timestamp`。
- 纯日期字段应为 `date`。
- 整数字段应为 `integer`。
- JSON快照、事件载荷、响应快照、步骤快照等结构化字段应为 `jsonb`。
- PostgreSQL DDL 中不允许出现 `datetime`、`decimal`、`int`、`auto_increment`、`tinyint` 等 MySQL 方言类型。

## 逻辑校验

- 业务编码字段应纳入唯一键建议。
- 明细表应有头表外键。
- 日志表应能追溯到来源业务对象。
- 接口表应能关联 `pro_interface_message`。
- 异常升级记录应关联异常主表。
- 强追溯关系尽量避免只使用泛型 ID。

## PowerShell 校验思路

建议用脚本检查：

```powershell
$data = Import-Csv .\MES系统基础表逐字段数据字典_按优先级_pgsql.csv

# 表数量、字段数量、主键数量
$data.Count
($data | Select-Object -ExpandProperty table_name -Unique).Count
($data | Where-Object primary_key -eq 'Y').Count

# 每表一个主键
$data | Group-Object table_name | Where-Object {
  (@($_.Group | Where-Object primary_key -eq 'Y')).Count -ne 1
}

# 重复字段
$data | Group-Object table_name,field_name | Where-Object Count -gt 1

# 外键引用存在性
$fieldSet = @{}
foreach ($x in $data) {
  $fieldSet[($x.table_name + '.' + $x.field_name)] = $true
}
$bad = @()
foreach ($r in ($data | Where-Object foreign_key -eq 'Y')) {
  if (-not $r.foreign_key_ref -or -not $fieldSet.ContainsKey($r.foreign_key_ref)) {
    $bad += $r
  }
}
$bad

# PostgreSQL 类型残留检查
$data | Where-Object { $_.data_type -in @('datetime', 'decimal', 'int', 'tinyint') }
```
