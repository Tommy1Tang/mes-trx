# 代码生成前检查清单

## 目标

在基于 PostgreSQL 适配版数据字典生成建表 SQL、Java 实体、Mapper、Service、Controller、前端页面前，确认数据模型已经达到开发输入标准。

默认输入文件：

- `../MES系统基础表逐字段数据字典_按优先级_pgsql.csv`
- `09_PostgreSQL数据库落地规范.md`

## 表级检查

- 表名是否符合 `pro_xxx` 命名。
- 表中文名是否清楚。
- 业务域是否明确。
- 优先级是否明确。
- 是否有主键。
- 是否有标准审计字段。
- 是否有 `del_flag`。
- 是否需要状态字段。
- 是否需要唯一键。
- 是否需要索引。

## 字段级检查

- 字段名是否符合命名规范。
- 字段说明是否通俗易懂。
- 字段类型是否合理。
- 字段长度是否足够。
- 是否必填是否符合业务。
- 默认值是否合理。
- 字典编码是否完整。
- 外键引用是否有效。
- PostgreSQL 类型是否已经完成适配。
- JSON快照、事件载荷、响应快照、步骤快照是否使用 `jsonb`。

## PostgreSQL DDL 检查

- 不允许出现 MySQL 方言类型，如 `datetime`、`auto_increment`、`tinyint`。
- `numeric` 字段必须带精度和小数位。
- `timestamp`、`date`、`time`、`text`、`jsonb` 不应带长度。
- 表名、字段名保持小写下划线，不使用双引号包裹标识符。
- 默认值字符串必须使用单引号。
- `del_flag` 默认值建议为 `'0'`。
- 高频表必须评估索引、分区和归档策略。

## Ruoyi 代码生成注意事项

- 主键字段建议为 `bigint`。
- PostgreSQL `bigint` 对应 Java `Long`。
- PostgreSQL `numeric` 对应 Java `BigDecimal`。
- PostgreSQL `timestamp` 对应 Java `LocalDateTime` 或项目统一时间类型。
- PostgreSQL `date` 对应 Java `LocalDate`。
- PostgreSQL `time` 对应 Java `LocalTime`。
- PostgreSQL `jsonb` 建议先按 `String` 或统一 JSON 类型处理。
- 逻辑删除字段建议统一为 `del_flag`。
- 创建和更新字段保持若依习惯：
  - `create_by`
  - `create_time`
  - `update_by`
  - `update_time`
  - `remark`
- 状态字段应能绑定字典。
- 下拉字段需要提前准备字典项。
- 外键显示字段需要明确关联查询来源。

## 不建议直接生成的情况

以下情况不建议直接生成代码：

- 表没有明确主键。
- 外键引用不存在。
- 状态字段没有字典编码。
- 字段说明大量英文残留。
- 表内字段含义重复。
- 泛型字段没有约束说明。
- 接口表没有消息主表关联。
- 追溯表不能明确来源和去向。
- 使用通用 CSV 直接生成 PostgreSQL DDL。
- 高频表没有索引、分区或归档设计。

## 生成顺序建议

1. 主数据表。
2. BOM 与工艺表。
3. 工单与执行表。
4. 质量与异常表。
5. 追溯表。
6. 接口与映射表。
7. MBR/EBR 与执行引擎表。
8. 数据采集、SCADA 和运行时韧性表。

## 生成后人工补充

代码生成后通常还需要人工补充：

- 字典下拉配置。
- 外键关联显示字段。
- 唯一性校验。
- 状态流转校验。
- 删除前依赖校验。
- 导入导出模板。
- 业务按钮权限。
- 查询条件优化。
