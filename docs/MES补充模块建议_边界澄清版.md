# MES 补充模块建议（边界澄清版）

## 1. 已明确的系统边界

| 能力域 | 责任归属 | MES 处理口径 |
|---|---|---|
| 线边仓 | MES 自管 | 需要补线边仓库存、入出库、领退料、盘点、预警、物料平衡等能力 |
| 设备点检/保养/维修 | SAP PM | MES 不自建设备维保维修和备品备件库存，只接收设备可用状态、维保到期/锁定状态、维修状态等必要信息 |
| 备品备件 | SAP PM | MES 不管理备件库存和出库，只在必要时引用 SAP PM 的维修/保养结果 |
| 培训计划/培训记录 | 专门培训系统 | MES 不管理培训计划和培训记录，只保留人员资质、岗位/工序/设备授权和有效期 |
| SOP/文档生命周期 | PLM + 文控系统 | MES 不管理 SOP 文档版本生命周期，只保存文档引用、工序绑定关系和查看入口 |
| 高频设备数据 | ThingsBoard/SCADA | MES 保存关键采集结论、摘要、告警和批记录证据，不保存全量高频原始时序 |
| SAP 计划和账务 | SAP ERP | MES 接收订单/物料/BOM/Routing 等参考数据，投料/报工/检验通过 Outbox 异步回传 |

### 2.3 线边仓与生产物料管理

你已经明确 WMS 不管线边仓，所以线边仓必须作为 MES 的正式业务域，而不是只靠仓库主数据和投退料硬撑。

进一步明确后的业务闭环：

1. 生产在 MES 按工序创建领料单，领料需求应关联工单、工序、MBR Step、物料、需求数量、需求批次或批次规则。
2. MES 将领料申请发送给 WMS，WMS 负责从库房侧拣配和移库。若相同物料、相同批次存在多条需求，WMS 可以合并后一次移库到线边仓。
3. WMS 完成移库后回传实际移库结果，MES 需要把 WMS 合并后的实物结果拆分或映射回原始工序领料需求，不能丢失“这批料原本服务哪些工序/工单”的关系。
4. 物料进入线边仓后，由 MES 建立线边仓库存台账。线边仓库存不再由 WMS 管理，但需要保留 WMS 移库单号、来源仓库、来源库位、批次、数量等来源证据。
5. 生产从线边仓进行领用投料，MES 记录生产领用和实际投料。单件码物料必须逐码扫描和追踪，非单件码物料按批次和数量管理。
6. 生产结束或阶段完成后，如有剩余物料，生产在 MES 发起退料申请并传给 WMS，由库房执行实物退料。WMS 回传确认后，MES 冲减线边仓库存并记录退料闭环。
7. 生产需要定期对线边仓进行盘库清理，盘点差异需要记录原因、复核和调整流水。

建议新增模块：

- 线边仓库存台账
- 线边仓入库/接收
- 生产领料
- 物料分发
- 物料移除
- 生产补料
- 生产退料
- 物料数量调整
- 线边仓盘点
- 库存预警
- 单件码/非单件码投料管理
- WMS 移库合并结果映射

建议新增表：

| 表名 | 中文名称 | 用途 |
|---|---|---|
| `pro_material_requisition` | 生产领料单表 | 记录生产按工序发起的领料申请，关联工单、工序、工作中心和需求时间 |
| `pro_material_requisition_item` | 生产领料明细表 | 记录工序维度的物料、需求数量、需求批次、替代料规则和状态 |
| `pro_wms_transfer_result` | WMS移库结果表 | 记录 WMS 合并拣配、移库到线边仓后的实际结果 |
| `pro_wms_transfer_result_item` | WMS移库结果明细表 | 记录 WMS 实际移库的物料、批次、数量、来源仓库、目标线边仓 |
| `pro_material_requisition_wms_map` | 领料需求与WMS移库映射表 | 解决 WMS 合并移库后，实际移库明细与 MES 原始工序需求的对应关系 |
| `pro_lineside_inventory` | 线边仓库存表 | 保存车间线边仓物料批次、数量、状态、库位和来源移库信息 |
| `pro_lineside_inventory_unit` | 线边仓单件码库存表 | 保存单件码/序列号物料在线边仓的逐码状态、位置和来源 |
| `pro_lineside_inventory_txn` | 线边仓库存流水表 | 记录入库、领料、分发、投料、退料、调整、盘点等库存变动 |
| `pro_material_distribution` | 物料分发记录表 | 记录从线边仓到工单/批次/工序的物料分发 |
| `pro_material_distribution_item` | 物料分发明细表 | 记录分发物料批次、数量、库位和校验结果 |
| `pro_material_removal_record` | 物料移除记录表 | 记录已分发或已上料物料的移除动作 |
| `pro_material_replenishment` | 生产补料记录表 | 记录生产过程中的补料申请、审批和执行 |
| `pro_operation_consumption_unit` | 投料单件码明细表 | 记录单件码物料投料时逐码扫描和消耗明细 |
| `pro_lineside_return` | 生产退料单表 | 记录生产余料、异常料退回库房的退料申请，并发送给 WMS |
| `pro_lineside_return_item` | 生产退料明细表 | 记录退料物料、批次、数量、单件码范围、退料原因和 WMS 确认状态 |
| `pro_lineside_stocktake` | 线边仓盘点单表 | 记录盘点任务、盘点范围、状态和结果 |
| `pro_lineside_stocktake_item` | 线边仓盘点明细表 | 记录账面数量、实盘数量、差异和原因 |
| `pro_lineside_stocktake_unit` | 线边仓单件码盘点明细表 | 记录单件码物料盘点时逐码实盘、缺失、盈余和异常状态 |
| `pro_inventory_warning_rule` | 库存预警规则表 | 定义安全库存、效期、冻结、超储、低储等预警规则 |
| `pro_inventory_warning_event` | 库存预警事件表 | 记录库存预警触发、处理和关闭 |

关键建模原则：

- 领料申请按工序发起，WMS 可以按物料批次合并移库，但 MES 必须保留原始工序需求与 WMS 合并结果的映射。
- 线边仓库存由 MES 管理，WMS 只负责库房到线边仓、线边仓回库房的实物移动执行和回传。
- 单件码物料按 `pro_lineside_inventory_unit` 和 `pro_operation_consumption_unit` 逐码管理；非单件码物料按 `pro_lineside_inventory` 的批次数量管理。
- 投料消耗以 MES 记录为准，退料必须先在 MES 发起，再由 WMS 执行库房退料确认。
- 盘点差异不能直接改库存，必须通过 `pro_lineside_stocktake`、`pro_lineside_stocktake_item` 和 `pro_lineside_inventory_txn` 留痕。

### 2.9 移动端/PDA/iPad

PDA/iPad 主要是前端形态，不是独立数据域。当前核心执行表可以支撑大部分移动端操作，但要补两个平台能力：

- 移动端操作权限与菜单配置可以复用 RuoYi 权限体系。
- 弱网重复提交必须走 `pro_idempotency_request`。

暂不建议为 PDA/iPad 单独建业务表，除非后续要做离线缓存和离线补传。

### 2.10 PLM MBR 接收与 Excel 批导控制

你们已经明确 MBR 的设计、版本审批、生效、冻结均在 PLM 完成。MES 不做 MBR 主生命周期管理，只接收 PLM 已批准的结构化 MBR 镜像，并在工单下达时生成执行快照。

当 PLM 暂时无法满足结构化传输时，MES 可以提供 Excel 批导作为受控补充入口，但 Excel 批导必须等同于接口接收，不能绕过版本、校验、审计和权限控制。

建议新增模块：

- PLM MBR 接收批次管理
- Excel MBR 批导
- MBR 结构完整性校验
- 导入错误明细
- 来源文件留存和哈希校验
- PLM 版本与 MES 镜像版本映射

建议新增表：

| 表名 | 中文名称 | 用途 |
|---|---|---|
| `pro_mbr_import_batch` | MBR导入批次表 | 记录一次 PLM 接口接收或 Excel 批导的导入批次 |
| `pro_mbr_import_item` | MBR导入明细表 | 记录导入批次下的 MBR、版本、阶段、步骤、参数、物料等对象处理情况 |
| `pro_mbr_import_validate_log` | MBR导入校验日志表 | 记录结构完整性、字段合法性、版本一致性、引用对象存在性等校验结果 |
| `pro_mbr_import_error` | MBR导入错误明细表 | 记录导入失败、校验失败、字段缺失、字典不合法、对象不存在等错误 |
| `pro_mbr_source_file` | MBR来源文件表 | 保存 Excel 文件名、文件哈希、上传人、上传时间、版本说明和存储链接 |
| `pro_mbr_source_map` | PLM MBR来源映射表 | 记录 PLM MBR ID、版本号、MES 镜像 MBR ID、接收状态和生效范围 |

关键建模原则：

- PLM 是 MBR 主版本源，MES 中的 `pro_mbr_*` 是已批准 MBR 的执行镜像。
- MES 接收 MBR 后只做结构校验和镜像落库，不替代 PLM 做审批发布。
- Excel 批导必须走相同校验逻辑，并保留文件哈希和审计追踪。
- 工单执行不能实时读取 PLM，必须引用 `pro_mbr_execution_context` 中的执行快照。
- PLM 改版影响运行中工单时，MES 只执行 Safe Hold 和上下文刷新，不在 MES 内重新审批 MBR。

|---|---|---|
| `pro_dhr_template` | 批记录模板表 | 定义批记录/DHR模板主体、版本、状态、适用产品和适用范围 |
| `pro_dhr_template_node` | 批记录模板节点表 | 定义模板目录、章节、段落、表格和附录结构 |
| `pro_dhr_data_source` | 批记录取数来源表 | 配置 EBR、检验、称量、采集、异常、签名、追溯等取数来源 |
| `pro_dhr_field_mapping` | 批记录字段映射表 | 配置模板字段与业务数据字段、聚合规则、格式化规则的映射关系 |
| `pro_dhr_render_task` | 批记录生成任务表 | 记录按工单/批次/SN 生成批记录的任务、状态和触发来源 |
| `pro_dhr_render_result` | 批记录生成结果表 | 记录生成文件、PDF链接、模板版本、生成时间、生成结果和校验状态 |
| `pro_dhr_render_log` | 批记录生成日志表 | 记录取数、渲染、失败、重试、人工干预等过程 |

关键建模原则：

- MBR 决定怎么生产，EBR 记录实际执行，DHR 模板只决定最终怎么展示。
- 批记录模板不能反向修改执行数据，也不能覆盖 EBR 原始事实。
- 同一批次生成批记录时，必须绑定模板版本和数据快照时间。
- 模板取数失败要可追溯，不能静默生成缺字段批记录。
- 批记录重生成必须保留历史版本和审计记录。

## 3. 不建议纳入 MES 的能力

| 能力 | 不纳入原因 | MES 保留能力 |
|---|---|---|
| 设备点检计划、保养计划、维修工单、备品备件库存 | SAP PM 已负责，MES 自建会造成双系统台账和责任边界冲突 | 引用设备状态、维保到期状态、设备锁定/解锁状态、维修结果 |
| 培训计划、培训需求、培训记录 | 专门培训系统负责 | MES 只保存 `pro_person_qualification`，用于工序/设备/洁净区操作资质校验 |
| SOP文档生命周期、文档审批、文档版本发布 | PLM + 文控系统负责 | MES 只保存 SOP 引用、版本号、文档链接、工序绑定和查看入口 |
| 高频时序数据 | ThingsBoard/SCADA 负责 | MES 保存摘要、判定、曲线链接和 EBR 证据 |
| SAP 财务库存、成本、MRP | SAP ERP 负责 | MES 保存执行证据，并异步回传 |

## 5. 对现有 147 张表的影响

当前 147 张表不需要推倒重来，建议按“补充业务域”方式增量扩展：

- 线边仓和物料平衡是必须补的业务表。
- PLM MBR 接收、Excel 批导控制和来源映射是必须补的接口/导入控制表。
- DHR/批记录模板取数、渲染任务和生成结果是必须补的批记录输出表。
- 表单、DHR 模板、流程、编码是必须补的平台表。
- 批次事件和过站事件是必须补的执行过程表。
- AQL、标签、包装、UDI 是二期增强表。
- 设备维保、备件、培训计划、SOP生命周期不补 MES 主数据表，只保留引用和接口字段。

这套补充后，MES 的边界会更干净：生产现场归 MES，设备资产维保归 SAP PM，人员培训归培训系统，文档生命周期归 PLM/文控，线边仓归 MES。
